# 桌面端适配与两步下单 · 实施约定 v1.0

> 背景：用户反馈「界面看起来是手机端的界面，网页端做得不太好」+「内容全挤在一页，应该先选服务、确认后再填信息提交」。
> 本文是本次改造的**唯一实施口径**，所有改动必须先读本文。
> 关系文档：`docs/prd/Xiuxiu_UIUX_Design_v1.1.md` §4（布局与栅格）、§6.10（底部操作栏）、§7.14（后台桌面双栏）、§9.3（桌面端）。

## 1. 断点令牌（已落地）

`src/app/globals.css` 的 `@theme` 中已新增（**只读，不允许改**）：

```css
--breakpoint-tablet: 768px;    /* → tablet: 变体 */
--breakpoint-desktop: 1200px;  /* → desktop: 变体 */
```

| 档位 | 变体 | 宽度 | 规则（UIUX §4 / §9.3） |
| --- | --- | --- | --- |
| 移动（基准稿） | 无前缀 | < 768px | 单列；页面边距 16px；分组卡片满宽；**底部固定操作栏** |
| 平板 | `tablet:` | ≥ 768px | 单列居中，内容最大宽 640px；页面边距 24px；**底部操作栏取消固定，改为表单内按钮** |
| 桌面 | `desktop:` | ≥ 1200px | 容器最大宽 1200px；表单区最大宽 560px；Hero 全宽背景；可使用两栏 |

**硬约束**：移动端（< 768px）现有视觉与交互**一个像素都不许变**。
新增/修改的类名必须带 `tablet:` / `desktop:` 前缀，或者放在 `@media (min-width: 768px)` 内。
不允许把原来的移动端类名删掉换成别的写法——只能追加断点变体。

## 2. 容器与边距统一写法

```tsx
/* 单列页面（默认） */
<div className="mx-auto w-full max-w-[40rem] px-4 tablet:px-6">

/* 需要桌面两栏的页面 */
<div className="mx-auto w-full max-w-[40rem] px-4 tablet:px-6 desktop:max-w-[75rem]">
  <div className="desktop:grid desktop:grid-cols-[minmax(0,560px)_360px] desktop:justify-center desktop:gap-10">
    <div>{/* 主列 */}</div>
    <aside className="hidden desktop:block">{/* 侧栏，吸顶 sticky top-20 */}</aside>
  </div>
</div>
```

- 页面左右边距：`px-4 tablet:px-6`
- 正文段落最大宽：`max-w-[45rem]`（≈720px，UIUX §3.2）
- 不新增横向滚动条：1440px 下必须 `document.documentElement.scrollWidth <= innerWidth`

## 3. 底部操作栏规则（UIUX §6.10 例外条）

现状：C 端各页用 `fixed inset-x-0 bottom-0 ... glass-bar` 自绘操作栏。

改造后：

```tsx
{/* 移动端固定栏 + 平板起取消固定，改为表单内按钮 */}

{/* 方式 A：同一份按钮，靠定位切换（推荐，避免重复 DOM 造成重复提交） */}
<div className="glass-bar fixed inset-x-0 bottom-0 z-(--z-footer) border-t-[0.5px] border-separator px-4 pt-3 pb-[calc(var(--space-3)+env(safe-area-inset-bottom,0px))] tablet:static tablet:mt-6 tablet:border-0 tablet:bg-transparent tablet:p-0 tablet:backdrop-blur-none">
  ...
</div>
```

> ⚠️ **绝对禁止**为了「桌面好看」而把提交按钮渲染成两份 DOM（移动一份 + 桌面一份）。
> 上一轮已知问题：提交同时绑在 `<form onSubmit>` 与 `<Button onClick>` 上，会重复下单。
> 本次改造**不得新增**第二条提交路径：保留现有的「form onSubmit + Button onClick 双绑定」现状即可，**不要**再叠加。

同时：页面主容器在移动端保留 `pb-bottom-bar`，平板起不需要该预留：

```tsx
<main className="... pb-bottom-bar tablet:pb-10">
```

## 4. 两步下单流程契约（`/order`）

### 4.1 步骤与内容划分

| 步骤 | 标题 | 内容 |
| --- | --- | --- |
| Step 1 | 选择服务 | 服务类型 Segmented（清灰换硅脂 / 其他问题）<br>· clean → 两档套餐卡（¥80 标准 / ¥100 深度清洁·推荐）<br>· other → Info 价格说明 + 问题类型 Chip 多选 + 字段错误位 |
| Step 2 | 填写信息 | 联系信息（联系人 / 电话 / 品牌型号 / 示例图 / 型号照片 ≤3 / 故障或补充描述）<br>联系方式（联系偏好 Segmented + QrCard 高亮）<br>服务方式与时间（服务方式 Segmented + 上门 Warning 条 + 期望时间 Bottom Sheet + 上门地址）<br>提交 |

- **Step 1 不得出现**任何联系信息、联系方式、服务方式、地址输入。
- **Step 2 不得重复**出现服务类型/套餐/问题类型选择（只在摘要里以只读文本展示）。

### 4.2 步骤条

```
① 选择服务 ──── ② 填写信息
```

- 位置：Hero 之下、第一个分组卡片之上；移动端与桌面同一结构。
- 当前步：主色实心圆 + 序号，文字 `font-semibold text-primary`。
- 已完成/可返回步：可点击（`<button type="button">`），点击回到该步且**保留全部已填状态**。
- 未来步：禁用（`disabled`，`text-label-3`）。
- 语义：`<ol>` + `aria-current="step"`。

### 4.3 导航与按钮

| 位置 | Step 1 | Step 2 |
| --- | --- | --- |
| 移动端固定底栏 | 左价格摘要 + 主按钮「下一步 · 填写信息」 | 左价格摘要 + 主按钮「提交订单」 |
| Step 2 表单顶部（步骤条下方或 Step 1 摘要旁） | — | 次级文字按钮「← 上一步」（`variant="secondary"` 或 ghost，`type="button"`） |
| ≥768px | 表单内主按钮「下一步 · 填写信息」 | 表单内主按钮「提交订单」+「← 上一步」 |

- Step 1 的「下一步」：先做 Step 1 校验，通过才 `setStep(2)`，并 `window.scrollTo({ top: 0 })`（平滑或即时均可，桌面务必回到顶部）。
- Step 2 的「上一步」：`setStep(1)`，不清空任何已填数据。

### 4.4 校验拆分

| 触发点 | 校验项 |
| --- | --- |
| Step 1 下一步 | `otherTypes`：other 类型且未选 → `请至少选择一个问题类型`（沿用现有文案与 `errors["otherTypes"]`） |
| Step 2 提交 | 现有 `validate()` 的其余全部规则，**一字不改**：contactName / phone（`^1[3-9]\d{9}$`）/ brandModel / description ≤300 / other+「其他」时描述必填 |
| 服务端字段错误回填 | 现有 `fields` → `setErrors` 逻辑保留；若错误字段属于 Step 1（`otherTypes`/`cleanTier`/`serviceType`），必须自动 `setStep(1)` 让用户看到 |

### 4.5 不得改变的部分（回归红线）

- 请求体字段名与取值口径：`serviceType` / `cleanTier` / `otherTypes` / `contactName` / `phone` / `contactPref` / `brandModel` / `modelPhotos` / `description` / `serviceMode` / `preferredTime` / `address`
  - `cleanTier: isOther ? null : tier`
  - `otherTypes: isOther ? types : null`
  - `address: mode === "home" && address.trim() ? address.trim() : null`
  - `modelPhotos: modelPhotos.length > 0 ? modelPhotos : null`，`description` 同理空串转 null
- 成功跳转：`/success?orderId=…&etaText=…&serviceType=…[&cleanTier=…]`
- 失败处理：字段级 → 定位到字段；非字段级 → Toast + 保留已填内容
- `preferredTime` 默认值 `"尽快"`、`tier` 默认 `"basic80"`、`pref` 默认 `"phone"`、`mode` 默认 `"shop"`
- 底部价格摘要口径：clean → `¥80.00`/`¥100.00` + ` 起`；other → `联系报价`
- 所有 `constants` 文案（`HOME_SERVICE_NOTICE`、`OTHER_PRICE_NOTICE`、`WARRANTY` 等）不得改写
- Hero 入口卡行为：点击后选中对应服务类型，**停留在 Step 1**（不要直接跳 Step 2）

### 4.6 桌面两栏（≥1200px）

- 左列：Step 内容（步骤条 + 分组卡片 + 表单内按钮），宽 ≤560px。
- 右列：**吸顶摘要卡**（`sticky top-20`，宽 360px），只读展示：
  - 当前服务：`清灰换硅脂 · 标准 ¥80` / `清灰换硅脂 · 深度清洁 ¥100` / `其他问题 · N 项已选`
  - 价格摘要（同底栏口径）
  - `✓ 含 7 天保修`（仅 clean）
  - 官方微信二维码（`QrCard size={128}`）
  - 联系电话 `tel:` 链接（`SHOP_PHONE`）
- 右列在 `<1200px` 完全隐藏（`hidden desktop:block`），不得在平板上占位。

## 6. 桌面视觉细则

1. **Hero**：桌面 `desktop:min-h-[min(56vh,460px)]`，内容层 `max-w-[75rem]`，两个入口卡 `tablet:max-w-[32rem]`（不要横铺满 1200px）。
2. **导航栏**：`tablet:` 起小标题常显（`opacity-100`），不依赖滚动进度；高度仍 52px。
3. **卡片间距**：桌面分组间距可放大到 32px（`tablet:mt-8`），不要出现一屏塞满。
4. **hover**：所有新增 hover 态必须包在 `@media (hover: hover)` 语义内（Tailwind 用 `hover:` 即可，但不要在触屏设备上依赖 hover 传达信息）。
5. **焦点环**：桌面键盘可达，`focus-visible:` 需清晰（沿用现有 `Button` 组件的焦点样式，不要覆盖）。
6. **成功页/售后页**：桌面居中、`max-w-[40rem]`，卡片使用统一 `rounded-card`；不要出现 1200px 宽的单行文本。
7. **后台**：`AdminNav` 在 `tablet:` 起固定为一行；`desktop:` 起按 §7.14 双栏（列表 360–420px 可滚动 + 详情）。
